In this hands-on lab, you will gain practical experience in manipulating directory data within your Red Hat Directory Server 13 instance. You'll learn how to add, modify, and delete entries, and how to effectively import and export data using LDIF files. Furthermore, you will master the art of advanced LDAP searching, leveraging various filters and scopes to retrieve precise information from your directory.

== Prerequisites

Before starting this lab, ensure you have:

*   A running Red Hat Directory Server 13 instance, preferably one you deployed and configured in a previous lab.
*   SSH access to the RHEL 9 system hosting your RHDS instance.
*   Administrative credentials for your RHDS instance (e.g., `cn=Directory Manager`).
*   The `openldap-clients` package installed on your client or server system to use `ldapadd`, `ldapmodify`, `ldapdelete`, and `ldapsearch`.

sudo dnf install -y openldap-clients

== Task 1: Add New Directory Entries

In this task, you will add new user and group entries to your directory using the `ldapadd` command. We'll start by creating an LDIF file.

=== Step 1.1: Create an LDIF file for a new user

An LDIF (LDAP Data Interchange Format) file is a plain text file that specifies a set of LDAP operations (add, modify, delete) to be performed.

1.  Create a file named `new_user.ldif` with the following content:

    [source,ldif]
    ----
    dn: uid=jdoe,ou=People,dc=example,dc=com
    objectClass: top
    objectClass: person
    objectClass: organizationalPerson
    objectClass: inetOrgPerson
    uid: jdoe
    cn: John Doe
    sn: Doe
    givenName: John
    mail: jdoe@example.com
    description: Employee John Doe
    userPassword: password123
    ----

    *   `dn`: The Distinguished Name (DN) uniquely identifies the entry. It must be unique within the directory.
    *   `objectClass`: Defines the types of objects this entry represents. Each object class defines a set of mandatory and optional attributes. `inetOrgPerson` is commonly used for user accounts.
    *   `uid`, `cn`, `sn`, `givenName`, `mail`, `description`: Common attributes for a user entry.
    *   `userPassword`: The user's password. This will be hashed by the server upon addition.

2.  Save the file.

=== Step 1.2: Add the new user entry

Use the `ldapadd` command to add the entry defined in `new_user.ldif` to your RHDS instance.

[source,bash]
----
ldapadd -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -f new_user.ldif
----

*   `-x`: Use simple authentication.
*   `-H ldap://{host}:{port}`: Specifies the LDAP server host and port.
*   `-D "{binddn}"`: Specifies the DN to bind to the directory as (our Directory Manager).
*   `-w "{bindpw}"`: Specifies the bind password.
*   `-f new_user.ldif`: Specifies the input LDIF file.

You should see output indicating the operation was successful.

=== Step 1.3: Verify the new user entry

Use `ldapsearch` to confirm that the `jdoe` user has been added.

[source,bash]
----
ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "uid=jdoe,ou=People,dc=example,dc=com"
----

You should see the full entry for `jdoe`, including all attributes.

=== Step 1.4: Add a new organizational unit (OU) and group

Let's add an "IT" organizational unit and an "IT Users" group to our directory.

1.  Create a file named `new_ou_group.ldif` with the following content:

    [source,ldif]
    ----
    dn: ou=IT,dc=example,dc=com
    objectClass: top
    objectClass: organizationalUnit
    ou: IT

    dn: cn=IT Users,ou=Groups,dc=example,dc=com
    objectClass: top
    objectClass: groupOfNames
    cn: IT Users
    member: uid=jdoe,ou=People,dc=example,dc=com
    description: Members of the IT department
    ----

    *   The first entry defines an `organizationalUnit` named "IT".
    *   The second entry defines a `groupOfNames` named "IT Users" and includes `jdoe` as a member. The `groupOfNames` object class requires at least one `member` attribute.

2.  Add these entries using `ldapadd`:

    [source,bash]
    ----
    ldapadd -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -f new_ou_group.ldif
    ----

3.  Verify the entries:

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "ou=IT,dc=example,dc=com"
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "cn=IT Users,ou=Groups,dc=example,dc=com"
    ----

== Task 2: Modify Directory Entries

You will now modify existing entries, such as changing a user's email or adding an attribute to a group.

=== Step 2.1: Modify an existing user's attribute

Let's change John Doe's email address and add a title.

1.  Create a file named `modify_user.ldif` with the following content:

    [source,ldif]
    ----
    dn: uid=jdoe,ou=People,dc=example,dc=com
    changetype: modify
    replace: mail
    mail: john.doe@example.com
    -
    add: title
    title: Software Engineer
    -
    add: telephoneNumber
    telephoneNumber: +1 555 123 4567
    ----

    *   `changetype: modify`: Specifies that this LDIF entry is for a modification.
    *   `replace: mail`: Replaces the existing `mail` attribute value.
    *   `-`: A single hyphen separates modification operations within the same entry.
    *   `add: title`: Adds a new `title` attribute.
    *   `add: telephoneNumber`: Adds a new `telephoneNumber` attribute.

2.  Apply the modification using `ldapmodify`:

    [source,bash]
    ----
    ldapmodify -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -f modify_user.ldif
    ----

3.  Verify the changes using `ldapsearch`:

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "uid=jdoe,ou=People,dc=example,dc=com" mail title telephoneNumber
    ----

    You should see the updated email, the new title, and the new telephone number.

=== Step 2.2: Add another user to the "IT Users" group

Let's create a new user and then add them to the "IT Users" group.

1.  Create `new_user2.ldif`:

    [source,ldif]
    ----
    dn: uid=asmith,ou=People,dc=example,dc=com
    objectClass: top
    objectClass: person
    objectClass: organizationalPerson
    objectClass: inetOrgPerson
    uid: asmith
    cn: Alice Smith
    sn: Smith
    givenName: Alice
    mail: asmith@example.com
    userPassword: password456
    ----

2.  Add the user:

    [source,bash]
    ----
    ldapadd -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -f new_user2.ldif
    ----

3.  Create `add_group_member.ldif` to add `asmith` to the "IT Users" group:

    [source,ldif]
    ----
    dn: cn=IT Users,ou=Groups,dc=example,dc=com
    changetype: modify
    add: member
    member: uid=asmith,ou=People,dc=example,dc=com
    ----

4.  Apply the modification:

    [source,bash]
    ----
    ldapmodify -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -f add_group_member.ldif
    ----

5.  Verify the group membership:

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "cn=IT Users,ou=Groups,dc=example,dc=com" member
    ----

    You should see both `uid=jdoe,ou=People,dc=example,dc=com` and `uid=asmith,ou=People,dc=example,dc=com` listed as members.

== Task 3: Delete Directory Entries

This task demonstrates how to remove entries from the directory using `ldapdelete`.

=== Step 3.1: Remove a user from a group

Let's remove John Doe from the "IT Users" group.

1.  Create `remove_group_member.ldif`:

    [source,ldif]
    ----
    dn: cn=IT Users,ou=Groups,dc=example,dc=com
    changetype: modify
    delete: member
    member: uid=jdoe,ou=People,dc=example,dc=com
    ----

2.  Apply the modification:

    [source,bash]
    ----
    ldapmodify -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -f remove_group_member.ldif
    ----

3.  Verify the group membership again:

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "cn=IT Users,ou=Groups,dc=example,dc=com" member
    ----

    Only `asmith` should now be listed as a member.

=== Step 3.2: Delete a user entry

Now, let's delete the `jdoe` user entirely.

1.  Use `ldapdelete` to remove the entry:

    [source,bash]
    ----
    ldapdelete -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" "uid=jdoe,ou=People,dc=example,dc=com"
    ----

2.  Verify the deletion:

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "uid=jdoe,ou=People,dc=example,dc=com"
    ----

    You should receive a message like `No such object (32)`, indicating the entry has been successfully removed.

== Task 4: Import and Export Directory Data with LDIF

LDIF files are crucial for bulk operations, backups, and migrations.

=== Step 4.1: Export all entries from a specific base DN

You can export all entries under a specified base DN to an LDIF file.

1.  Export the `dc=example,dc=com` suffix content to `export_example.ldif`:

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "{suffix}" > export_example.ldif
    ----

2.  Examine the contents of `export_example.ldif`. You will see all entries and their attributes.

    [source,bash]
    ----
    less export_example.ldif
    ----

=== Step 4.2: Import data from an LDIF file

Let's demonstrate importing by first deleting the `asmith` user and the `IT Users` group, then re-adding them from a new LDIF file.

1.  Delete `asmith` and the `IT Users` group:

    [source,bash]
    ----
    ldapdelete -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" "uid=asmith,ou=People,dc=example,dc=com"
    ldapdelete -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" "cn=IT Users,ou=Groups,dc=example,dc=com"
    ----

2.  Verify their deletion.
3.  Create `import_data.ldif` with the entries for `asmith` and the `IT Users` group:

    [source,ldif]
    ----
    dn: uid=asmith,ou=People,dc=example,dc=com
    objectClass: top
    objectClass: person
    objectClass: organizationalPerson
    objectClass: inetOrgPerson
    uid: asmith
    cn: Alice Smith
    sn: Smith
    givenName: Alice
    mail: asmith@example.com
    userPassword: password456

    dn: cn=IT Users,ou=Groups,dc=example,dc=com
    objectClass: top
    objectClass: groupOfNames
    cn: IT Users
    member: uid=asmith,ou=People,dc=example,dc=com
    description: Members of the IT department
    ----

4.  Import the data:

    [source,bash]
    ----
    ldapadd -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -f import_data.ldif
    ----

5.  Verify the entries are back:

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "uid=asmith,ou=People,dc=example,dc=com"
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "cn=IT Users,ou=Groups,dc=example,dc=com"
    ----

== Task 5: Perform Advanced LDAP Searches

The `ldapsearch` command is incredibly powerful for querying your directory. You will now explore various search filters and scopes.

=== Step 5.1: Basic Search with Filters

A basic search finds entries matching a simple filter.

1.  Find all users with `objectClass=inetOrgPerson`:

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "{suffix}" "objectClass=inetOrgPerson"
    ----

2.  Find all users named Alice (based on `cn` attribute):

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "{suffix}" "cn=Alice Smith"
    ----

3.  Find all entries with `ou=People`:

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "{suffix}" "ou=People"
    ----

=== Step 5.2: Attribute Selection

You can specify which attributes to return in the search results to reduce output verbosity.

1.  Search for `asmith` and only return `cn`, `sn`, and `mail` attributes:

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "{suffix}" "uid=asmith" cn sn mail
    ----

2.  Return all user attributes, but exclude `userPassword`:

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "{suffix}" "uid=asmith" "*" -userPassword
    ----

    *   `*`: Returns all user attributes.
    *   `-userPassword`: Excludes the `userPassword` attribute.

=== Step 5.3: Advanced Search Filters (Logical Operators)

LDAP filters support powerful logical operators: `&` (AND), `|` (OR), `!` (NOT).

1.  Find users who are `inetOrgPerson` AND have `mail` attribute:

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "{suffix}" "(&(objectClass=inetOrgPerson)(mail=*))"
    ----

    *   `mail=*`: Checks if the `mail` attribute exists.

2.  Find entries that are either `inetOrgPerson` OR `groupOfNames`:

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "{suffix}" "(|(objectClass=inetOrgPerson)(objectClass=groupOfNames))"
    ----

3.  Find entries that are NOT `organizationalUnit`:

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "{suffix}" "(!(objectClass=organizationalUnit))"
    ----

4.  Find users named Alice OR John (if John was still present):

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "{suffix}" "(|(cn=Alice Smith)(cn=John Doe))"
    ----

=== Step 5.4: Advanced Search Filters (Comparison Operators)

LDAP supports various comparison operators:

*   `=` : Equality match (exact match)
*   `~=` : Approximate match (implementation-dependent, often case-insensitive or phonetic)
*   `>=` : Greater than or equal to (for ordered attributes like numbers, dates)
*   `<=` : Less than or equal to (for ordered attributes)
*   `*` : Wildcard match (`cn=A*` for names starting with A, `*smith*` for names containing smith)
*   `attribute=*` : Presence (attribute exists)
*   `!attribute=*` : Absence (attribute does not exist)

1.  Find entries where `cn` starts with "A":

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "{suffix}" "cn=A*"
    ----

2.  Find entries where `cn` contains "Smith":

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "{suffix}" "cn=*Smith*"
    ----

3.  Find entries where the `description` attribute exists (e.g., the IT Users group):

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "{suffix}" "description=*"
    ----

=== Step 5.5: Search Scopes

The search scope defines how deeply the directory tree is searched relative to the base DN.

*   `-s base`: Search only the entry specified by the base DN.
*   `-s one`: Search the entries immediately below the base DN (one level).
*   `-s sub`: Search the entire subtree below the base DN (default behavior).

1.  Search `dc=example,dc=com` with `base` scope (will only return the `dc=example,dc=com` entry itself):

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "{suffix}" -s base
    ----

2.  Search `dc=example,dc=com` with `one` scope (will return immediate children like `ou=People`, `ou=Groups`, `ou=IT`):

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "{suffix}" -s one
    ----

3.  Search for `ou=People` with `base` scope (returns only the `ou=People` entry):

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "ou=People,{suffix}" -s base
    ----

4.  Search for `ou=People` with `one` scope (returns immediate children of `ou=People`, e.g., `uid=asmith`):

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "ou=People,{suffix}" -s one
    ----

5.  Search for `ou=People` with `sub` scope (default, returns `ou=People` and all entries below it, like `uid=asmith`):

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "ou=People,{suffix}" -s sub
    ----

=== Step 5.6: Limit Search Results

You can limit the number of entries returned and the time a search runs using `-z` and `-l`.

1.  Limit the search to return only 1 entry:

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "{suffix}" -z 1
    ----

2.  Limit the search to a maximum of 5 seconds (not easily demonstrable with small directories but useful for large ones):

    [source,bash]
    ----
    ldapsearch -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" -b "{suffix}" -l 5
    ----

== Cleanup (Optional)

You can remove the entries created in this lab if you wish to start clean for future labs.

[source,bash]
----
ldapdelete -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" "uid=asmith,ou=People,dc=example,dc=com"
ldapdelete -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" "cn=IT Users,ou=Groups,dc=example,dc=com"
ldapdelete -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" "ou=People,dc=example,dc=com"
ldapdelete -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" "ou=Groups,dc=example,dc=com"
ldapdelete -x -H ldap://{host}:{port} -D "{binddn}" -w "{bindpw}" "ou=IT,dc=example,dc=com"
----

[TIP]
====
When deleting OUs with entries under them, you need to delete the leaf entries first before deleting the parent OU. For instance, delete `uid=asmith,...` before deleting `ou=People,...`.
====
