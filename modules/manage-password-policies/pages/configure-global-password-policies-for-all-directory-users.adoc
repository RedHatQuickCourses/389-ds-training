#  Configure global password policies for all directory users.

// docs/modules/password-policies/pages/configure-global-password-policies.adoc

= Configure Global Password Policies

This section covers the configuration of global password policies in Red Hat Directory Server 13. Global password policies apply to all users within the directory tree, unless overridden by a more specific, fine-grained policy. Implementing a robust global password policy is a fundamental security measure, ensuring that all user accounts adhere to a baseline level of password strength and account management.

== Understanding RHDS Global Password Policies

Red Hat Directory Server (RHDS) enforces password policies to enhance security by dictating rules for password creation, expiration, and account lockout. These policies are crucial for preventing unauthorized access and maintaining the integrity of user accounts. A global password policy applies to all entries in the directory that are not subject to a more specific, subtree-level policy.

The global password policy is defined by a set of attributes stored under the entry `cn=Password Policy,cn=config`. This entry is part of the server's configuration directory information tree (DIT). When a user attempts to bind to the directory or modify their password, RHDS checks these attributes to ensure compliance.

Key attributes defining a password policy include:

*   `pwdMinLength`: Specifies the minimum number of characters required for a password.
*   `pwdMaxAge`: Defines the maximum lifetime (in seconds) of a password before it expires. A value of `0` means passwords never expire.
*   `pwdExpireWarning`: Sets the number of seconds before password expiration to start warning the user.
*   `pwdInHistory`: Determines the number of previous passwords that a user cannot reuse.
*   `pwdCheckQuality`: Enables or disables the server's internal password quality checks. A value of `1` often implies checking for dictionary words, common patterns, etc.
*   `pwdLockout`: A boolean (TRUE/FALSE) attribute that enables or disables account lockout functionality.
*   `pwdMaxFailure`: The maximum number of consecutive failed authentication attempts allowed before an account is locked.
*   `pwdFailureCountInterval`: The time window (in seconds) during which failed authentication attempts are counted. If this interval expires without further failures, the counter resets.
*   `pwdLockoutDuration`: The duration (in seconds) for which an account remains locked after `pwdMaxFailure` attempts. A value of `0` means the account must be manually unlocked.
*   `pwdGraceAuthNLimit`: The number of grace logins allowed after a password has expired.
*   `pwdAllowUserChange`: A boolean (TRUE/FALSE) attribute indicating if users are allowed to change their own password.
*   `pwdMinAge`: The minimum time (in seconds) that must pass before a user can change their password again.
*   `pwdMustChange`: A boolean (TRUE/FALSE) attribute that, when set to TRUE, forces a user to change their password upon their next successful bind. This is often used for newly created users or after a password reset by an administrator.
*   `pwdSafeModify`: A boolean (TRUE/FALSE) attribute that, when set to TRUE, requires the user to provide their current password when changing it.

By adjusting these attributes, administrators can enforce strong password practices across the entire directory service.

== Hands-on Lab: Configure Global Password Policies

This lab guides you through inspecting, modifying, and testing the global password policy in Red Hat Directory Server 13.

=== Prerequisites

*   A running Red Hat Directory Server 13 instance.
*   Administrative access to the RHDS instance (e.g., `cn=Directory Manager`).
*   Familiarity with command-line LDAP tools like `ldapsearch` and `ldapmodify`.

=== Procedure

==== Step 1: Inspect the Current Global Password Policy

Before making changes, it's good practice to view the existing global password policy.

. Log in to your RHDS server as `root` or a user with `sudo` privileges.
. Use `ldapsearch` to retrieve the global password policy configuration. Replace `_SERVER_NAME_` and `_LDAP_PORT_` with your RHDS instance details (e.g., `localhost` and `389` or `636` for LDAPS).

[source,bash]
----
ldapsearch -h _SERVER_NAME_ -p _LDAP_PORT_ -D "cn=Directory Manager" -W -b "cn=Password Policy,cn=config" objectclass="*"
----

.Example Output:
[source,text]
----

# filter: objectclass=*
# requesting: ALL

Review the output to understand the current settings, such as `pwdMinLength`, `pwdMaxAge`, and `pwdLockout`.

==== Step 2: Modify Global Password Policy Settings

We will create an LDIF file to update several policy attributes. For this example, let's configure:

*   Minimum password length: `10`
*   Password expiration: `90` days (`7776000` seconds)
*   Password history: `7` previous passwords
*   Account lockout: Enabled (`TRUE`), `5` failures, `5` minute interval (`300` seconds), `15` minute lockout duration (`900` seconds).
*   Force password change on first login for new users: `TRUE`

. Create a file named `global_password_policy.ldif` with the following content:

[source,ldif]
----
dn: cn=Password Policy,cn=config
changetype: modify
replace: pwdMinLength
pwdMinLength: 10
-
replace: pwdMaxAge
pwdMaxAge: 7776000
-
replace: pwdInHistory
pwdInHistory: 7
-
replace: pwdLockout
pwdLockout: TRUE
-
replace: pwdMaxFailure
pwdMaxFailure: 5
-
replace: pwdFailureCountInterval
pwdFailureCountInterval: 300
-
replace: pwdLockoutDuration
pwdLockoutDuration: 900
-
replace: pwdMustChange
pwdMustChange: TRUE
----

NOTE: Each attribute change is separated by a single hyphen (`-`) on its own line. This is crucial for `ldapmodify` to correctly parse multiple `replace` operations for the same entry.

. Apply the changes using `ldapmodify`. Replace `_SERVER_NAME_` and `_LDAP_PORT_` with your RHDS instance details.

[source,bash]
----
ldapmodify -h _SERVER_NAME_ -p _LDAP_PORT_ -D "cn=Directory Manager" -W -f global_password_policy.ldif
----

. You will be prompted for the Directory Manager password. Enter it to apply the changes.

.Example Output:
[source,text]
----
Enter LDAP Password:
modifying entry "cn=Password Policy,cn=config"
----

==== Step 3: Verify the Policy Changes

After applying the LDIF, re-run `ldapsearch` to confirm that the attributes have been updated.

[source,bash]
----
ldapsearch -h _SERVER_NAME_ -p _LDAP_PORT_ -D "cn=Directory Manager" -W -b "cn=Password Policy,cn=config" pwdMinLength pwdMaxAge pwdInHistory pwdLockout pwdMaxFailure pwdFailureCountInterval pwdLockoutDuration pwdMustChange

==== Step 4: Test the Global Password Policy

Let's create a test user and verify the configured policy.

. Add a new user entry (e.g., `uid=testuser01,ou=Users,dc=example,dc=com`) using an LDIF file. Create a file named `test_user.ldif`:

[source,ldif]
----
dn: uid=testuser01,ou=Users,dc=example,dc=com
objectClass: top
objectClass: person
objectClass: organizationalPerson
objectClass: inetorgperson
uid: testuser01
cn: Test User 01
sn: User01
userPassword: password
----

. Add the user to the directory. Replace `_SERVER_NAME_`, `_LDAP_PORT_`, and `_BASE_DN_` (e.g., `dc=example,dc=com`).

[source,bash]
----
ldapadd -h _SERVER_NAME_ -p _LDAP_PORT_ -D "cn=Directory Manager" -W -f test_user.ldif
----

. Try to bind as `testuser01` with the initial password "password".

[source,bash]
----
ldapwhoami -h _SERVER_NAME_ -p _LDAP_PORT_ -D "uid=testuser01,ou=Users,dc=example,dc=com" -W
----

You should receive a prompt to change the password due to `pwdMustChange: TRUE`.

.Example Output:
[source,text]
----
Enter LDAP Password:
ldap_bind: Constraint violation (19)
    additional info: Password must be changed
----

. Change the password for `testuser01`. You will need to provide the old password and the new password.
Let's try to set a new password that is *too short* (e.g., "short"). Create `change_password_short.ldif`:

[source,ldif]
----
dn: uid=testuser01,ou=Users,dc=example,dc=com
changetype: modify
replace: userPassword
userPassword: short
----

. Attempt to change the password:

[source,bash]
----
ldapmodify -h _SERVER_NAME_ -p _LDAP_PORT_ -D "uid=testuser01,ou=Users,dc=example,dc=com" -W -f change_password_short.ldif
----

. You will be prompted for the *old* password (`password`).
. The operation should fail, indicating a constraint violation due to `pwdMinLength`.

.Example Output:
[source,text]
----
Enter LDAP Password:
modifying entry "uid=testuser01,ou=Users,dc=example,dc=com"
ldap_modify: Constraint violation (19)
    additional info: Password fails quality check
----

. Now, change the password for `testuser01` to a valid, new password (e.g., "NewSecureP@ssword123"). Create `change_password_valid.ldif`:

[source,ldif]
----
dn: uid=testuser01,ou=Users,dc=example,dc=com
changetype: modify
replace: userPassword
userPassword: NewSecureP@ssword123
----

. Attempt to change the password:

[source,bash]
----
ldapmodify -h _SERVER_NAME_ -p _LDAP_PORT_ -D "uid=testuser01,ou=Users,dc=example,dc=com" -W -f change_password_valid.ldif
----

. You will be prompted for the *old* password (`password`). If successful, you can then bind with the new password.

.Example Output:
[source,text]
----
Enter LDAP Password:
modifying entry "uid=testuser01,ou=Users,dc=example,dc=com"
----

. Verify the successful password change by binding with the new password:

[source,bash]
----
ldapwhoami -h _SERVER_NAME_ -p _LDAP_PORT_ -D "uid=testuser01,ou=Users,dc=example,dc=com" -W
----

.Example Output:
[source,text]
----
Enter LDAP Password:
dn: uid=testuser01,ou=Users,dc=example,dc=com
----

This confirms the password was successfully changed and adhered to the `pwdMinLength` policy.

==== Step 5: Test Account Lockout Policy

Now, let's test the account lockout policy (`pwdLockout`, `pwdMaxFailure`, `pwdLockoutDuration`).

. Attempt to bind as `testuser01` with incorrect passwords multiple times (more than `pwdMaxFailure`, which is `5`).

[source,bash]
----
# Repeat this command at least 6 times, intentionally using a wrong password
ldapwhoami -h _SERVER_NAME_ -p _LDAP_PORT_ -D "uid=testuser01,ou=Users,dc=example,dc=com" -W
----

. After the configured number of failed attempts (`5`), the next bind attempt should fail with an account lockout error.

.Example Output (after several failed attempts):
[source,text]
----
Enter LDAP Password:
ldap_bind: Invalid credentials (49)
    additional info: Account locked
----

. You can verify the lockout status by searching for the user entry and inspecting the `pwdAccountLockedTime` attribute. This attribute will contain a timestamp if the account is locked.

[source,bash]
----
ldapsearch -h _SERVER_NAME_ -p _LDAP_PORT_ -D "cn=Directory Manager" -W -b "uid=testuser01,ou=Users,dc=example,dc=com" pwdAccountLockedTime
----

.Example Output (if locked):
[source,text]
----
Enter LDAP Password:
# extended LDIF
#
# LDAPv3
# base <uid=testuser01,ou=Users,dc=example,dc=com> with scope subtree
# filter: (objectclass=*)
# requesting: pwdAccountLockedTime
#

# Test User 01, Users, example, com
dn: uid=testuser01,ou=Users,dc=example,dc=com
pwdAccountLockedTime: 20230101120000Z

# search result
search: 2
result: 0 Success

# numResponses: 2
# numEntries: 1
----

. Wait for the `pwdLockoutDuration` (15 minutes in our configuration) to expire, or manually unlock the account.
To manually unlock the account, you can modify the user entry to delete the `pwdAccountLockedTime` attribute. Create `unlock_user.ldif`:

[source,ldif]
----
dn: uid=testuser01,ou=Users,dc=example,dc=com
changetype: modify
delete: pwdAccountLockedTime
----

. Apply the unlock operation using `ldapmodify`:

[source,bash]
----
ldapmodify -h _SERVER_NAME_ -p _LDAP_PORT_ -D "cn=Directory Manager" -W -f unlock_user.ldif
----

. You should now be able to bind as `testuser01` with the correct password.

[source,bash]
----
ldapwhoami -h _SERVER_NAME_ -p _LDAP_PORT_ -D "uid=testuser01,ou=Users,dc=example,dc=com" -W
----

This concludes the hands-on lab for configuring global password policies. You have successfully updated policy settings and tested their enforcement for password complexity, forced changes, and account lockout.
